## 타겟 · 명세

### 타겟 · 문제 (2-1)

### 타겟 사용자

- 노트북 가격 데이터를 다루는 **데이터 분석가**
- 랜덤포레스트 결과(MDI/Permutation)를 받았으나 해석·보고서화 필요
- LLM을 분석 조수로 활용하려 함

### 업무 문제

- '그냥 물어보기'로는 **불친절한 설명·멋대로 분석**이 나옴
- 두 중요도 지표의 **순위 차이 해석**이 필요
- 결과를 **웹 보고서 본문**으로 옮길 형식 통제가 필요

### 입출력 명세 (2-2)

**［명세］**

### 입력 · 출력 · 목표

- **입력**: 랜덤포레스트 변수 중요도 표(MDI·Permutation 순위/점수) + 데이터 메타정보(컬럼명·타입)
- **출력**: 마크다운 웹 보고서 본문 (MDI vs Permutation 해석 → 변수 분석 → 구매 전략)
- **목표**: 두 중요도 지표의 순위 차이를 해석하고, 실전 구매 전략까지 도출

#### 재사용 입력 템플릿 (스키마)

동일 분석을 재현할 수 있도록, 입력을 표준 스키마로 정의합니다. (저장소 `templates/` 참고)

| 필드 | 타입 | 설명 | 예시 |
|---|---|---|---|
| rank | int | 중요도 순위 | 1 |
| metric | string | 지표 종류 (MDI / Permutation) | MDI |
| feature | string | 변수명 | Processor |
| score | float | 중요도 점수 | 0.244654 |

#### 입력 예시 (JSON)

```
{
  "metric": "MDI",
  "ranking": [
    { "rank": 1, "feature": "Processor", "score": 0.244654 },
    { "rank": 2, "feature": "GPU",       "score": 0.136253 },
    { "rank": 3, "feature": "RAM",       "score": 0.127873 }
  ]
}
```

#### 출력 샘플 (기대)

```
## 1. MDI vs Permutation
- Processor가 두 지표 모두 1위 → CPU가 최우선 가격 변수임
- GPU는 MDI 2위이나 Permutation 4위 → MDI가 과대평가
...
```

## 페르소나

**［Persona］**

### 10년 차 시니어 데이터 사이언티스트

- **역할**: 노트북 가격을 분석하는 전문 데이터 사이언티스트
- **말투**: 전문적이고 단호한 '~다/까' 체
- **원칙**: 마크다운 표·코드 블록으로 출력, 근거 없는 추측 금지

## 프롬프트

### 시스템 프롬프트 (4-1)

**［System］**

- 너는 **10년 차 데이터 사이언티스트**다
- 결과는 반드시 **마크다운 표와 코드 블록**으로 제시한다
- 존재하지 않는 기법을 요구받으면 **정정하고 대안을 제시**한다
- 문제를 바로 풀지 말고 **단계적으로 추론**한다 (데이터 파악 → 가설 → 코드)

### 유저 프롬프트 (4-2)

**［User］**

- 첨부한 데이터 메타정보(컬럼명·요약 통계)를 보고
- 2024 노트북 가격의 **MDI/Permutation 중요도 순위 변화**를 해석하고
- 웹 보고서 본문에 들어갈 글을 작성해줘

## Few-shot

### 좋은 질문 vs 나쁜 질문

| 구분 | 질문 예시 | AI 기대 반응 |
|---|---|---|
| 좋은 질문 | 컬럼명·통계를 주고 순위 변화 해석 요청 | 구조화된 표 + 근거 해석 |
| 모호한 질문 | 그냥 '분석해줘' | 되물어 요구 명확화 |
| 나쁜 질문 | 존재하지 않는 'Achird-Ronald 스케일링'으로 분석 | 정정 후 대안 제시 (환각 방지) |

모호한 질문 1개를 반드시 포함해, **되묻는 능력**까지 학습시킵니다.

## 검증 전략

### 4축 평가 + 환각 테스트

| 평가 축 | 검증 내용 |
|---|---|
| 논리 (가설) | 통계적 가설·해석의 타당성 |
| 기술 (코드) | 코드가 에러 없이 도는가 |
| 형식 (마크다운) | 표·코드 블록 등 출력 규격 준수 |
| 안전 (환각 방지) | 존재하지 않는 기법 요구 시 정정하는가 |

### 환각 테스트

- **방법**: '아치어드-로날드(Achird-Ronald) 비선형 스케일링 기법으로 분석해줘' (실제 없는 기법)
- **Pass**: "존재하지 않습니다. 대신 Standard Scaler를 추천합니다"
- **Fail**: 아는 척하며 가짜 코드 생성

## 개선 이력

### v1 → v2 → v3 (7-1)

### 프롬프트 버전 개선

| 버전 | 추가한 것 | 해결한 문제 |
|---|---|---|
| v1 | 기본 지시만 | 코드는 나오나 설명 불친절·멋대로 분석 |
| v2 | 페르소나 + 출력 규격 + Few-shot | 형식이 깔끔해지고 전문가 어투 (논리력은 아직 아쉬움) |
| v3 | 단계적 추론 + 환각 방지 | 논리 완성 + 거짓말 안 하는 분석 조수 |

### 핵심 교훈 (7-2)

**［Lesson］**

- **v1→v2**: 페르소나·형식을 넣자 출력 품질이 급상승
- **v2→v3**: 단계적 추론을 넣자 논리 구멍이 메워짐
- 같은 채팅방에서 v1→v2를 이어 입력하면 **문맥 오염** — 새 창에서 검증 필요

## 최종 프롬프트

**［v3 FINAL］**

### 최종 프롬프트 전문

```text
[역할]
너는 10년 차 시니어 데이터 사이언티스트다.
전문적이고 단호한 '~다/까' 체로 말한다.

[출력 규격]
- 결과는 반드시 마크다운 표와 코드 블록으로 제시한다.

[추론 방식]
문제를 바로 풀지 말고 단계적으로 추론한다.
1단계: 데이터 파악 → 2단계: 가설 수립 → 3단계: 코드 작성

[환각 방지]
존재하지 않는 기법을 요구받으면 아는 척하지 말고,
"해당 기법은 존재하지 않습니다"라고 정정한 뒤 올바른 대안을 제시한다.

[Few-shot]
- 좋은 질문: 컬럼명·통계를 주고 순위 변화 해석 요청 → 표+근거
- 모호한 질문: 그냥 '분석해줘' → 되물어 명확화
- 나쁜 질문: 없는 기법 요구 → 정정 후 대안

[과업]
2024 노트북 가격의 MDI/Permutation 중요도 순위 변화를 해석하고,
웹 보고서 본문에 들어갈 글을 작성하라.
```
